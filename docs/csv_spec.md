# CSV 資料格式規格

所有測試資料一律依照本規格儲存，由 `analysis/serial_logger.py` 自動產生。

## 檔名

```
YYYYMMDD_<測試代號>_<第幾次>.csv
```

例：`20261015_A_1.csv`、`20261015_A_2.csv`、`20260928_fake_1.csv`

同一天同一測試重複執行時，第幾次會自動遞增，不會覆蓋舊檔。

## 存放位置

| 資料夾 | 內容 | 規則 |
|---|---|---|
| `logs/raw/` | 原始記錄 | **存了就不修改**，這是模型驗證的依據 |
| `logs/processed/` | 清理後的資料、圖表 | 可以重新產生 |

## 檔頭

以 `#` 開頭，記錄測試條件。pandas 讀取時加上 `comment="#"` 會自動略過。

```
# test_id: A
# fw_version: 0.1.0
# date: 2026-10-15 14:30
# load: none
# location: 實驗室 B203
# operator: 陳定波
# note: 風扇全速
```

| 欄位 | 說明 |
|---|---|
| test_id | 測試代號：fake、A、B、C、D、E… |
| fw_version | 韌體版本，自動讀取 `firmware/include/config.h` |
| date | 開始記錄的時間 |
| load | 罩內負載：`none`、`water_500g`… |
| location | 測試地點 |
| operator | 操作人員 |
| note | 其他需要記下的條件 |

## 資料欄位

| 欄位 | 單位 | 小數位 | 說明 |
|---|---|---|---|
| t_ms | ms | 0 | ESP32 開機後經過的時間 |
| mode | – | 0 | 0 關閉、1 致冷、9 故障 |
| duty | – | 3 | TEC 輸出比例，0.000（關閉）到 1.000（全速致冷） |
| t_in | °C | 2 | 罩內溫度（DHT22） |
| rh_in | % | 1 | 罩內相對濕度（DHT22） |
| t_cold | °C | 2 | TEC 冷端溫度（DS18B20） |
| t_hot | °C | 2 | TEC 熱端溫度（NTC） |
| t_amb | °C | 2 | 環境溫度（DS18B20，罩外） |
| v_bus | V | 3 | 電池電壓（INA226） |
| i_bus | A | 3 | 總電流（INA226） |
| p_bus | W | 2 | 總功率（INA226） |
| lid | – | 0 | 0 蓋著、1 打開（測試時手動按鈕標記） |

## 規則

1. **讀取失敗填 `nan`，不可填 0。** 填 0 會讓擬合程式以為溫度真的掉到 0°C，整條曲線被拉歪。
2. **取樣週期固定 2000 ms。** `serial_logger.py` 會偵測偏離超過 10% 的間隔並顯示「間隔異常」。
3. **序列埠上的資料行以 `D,` 開頭**，其他行視為除錯訊息，不寫入 CSV。
